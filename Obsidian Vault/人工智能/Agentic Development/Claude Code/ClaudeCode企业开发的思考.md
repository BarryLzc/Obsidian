## 安全与合规问题

- **敏感数据泄露风险：** Claude Code 需要读取本地文件上下文。如果项目配置文件（如 `.env`）或代码中硬编码了 API Key、数据库连接字符串，这些信息可能会随上下文发送至 Anthropic 服务器。
- **配置注入漏洞 (RCE)：** 2026 年初的研究发现，Claude Code 的 `.claude/settings.json` 存在被恶意利用的风险。如果开发者克隆了一个带有恶意配置的仓库，Claude Code 可能会在未授权的情况下执行 shell 命令。
- **代码所有权与合规性：** 生成的代码是否包含 GPL 等传染性协议的代码片段？大规模生成的代码可能引发知识产权（IP）审计的困难。

## 工程质量的腐化

**AI 擅长写“能跑通”的代码，但不擅长维护“长青”的架构。**
- **架构一致性缺失：** AI 在处理局部需求时，往往会绕过现有的设计模式。例如，它可能为了快速实现功能而引入重复逻辑，或破坏原有的领域驱动设计（DDD）边界。
- **技术债堆积：** 随着项目规模扩大，Claude Code 的上下文窗口虽然很大，但仍会发生“长程遗忘”，导致生成的补丁代码与系统全局状态冲突，产生难以调试的副作用。
- **评审成本激增：** 当 AI 一次性生成几百行代码时，人工 Code Review 的压力巨大。如果审阅者因为信任 AI 而放水，系统中会迅速填充大量逻辑陷阱。

## AI实际协作问题

**互联网产品的研发不仅仅是写代码，还涉及复杂的协作工作。**
- **生产环境压力下的问题**：Claude Code不知道生产环境的限流策略、CDN配置或特定中间件限制。它生成的代码在本地测试通过，但在高并发生产环境中可能导致OOM或者连接池耗尽。
- **文字的表现力有限**：现在没有agent可以参与评审会，Claude Code无法理解产品文档背后的“隐性业务逻辑”。
