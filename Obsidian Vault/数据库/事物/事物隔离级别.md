在数据库管理中，为了权衡**并发性能**和**数据一致性**，MySQL（主要指 InnoDB 引擎）提供了四种事务隔离级别。而支撑这些隔离级别的核心技术，就是 **MVCC（多版本并发控制）**。

---

## 一、 MySQL 四种事务隔离级别

隔离级别越高，数据一致性越好，但并发效率越低。

|**隔离级别**|**脏读 (Dirty Read)**|**不可重复读 (Non-repeatable Read)**|**幻读 (Phantom Read)**|**默认情况**|
|---|---|---|---|---|
|**读未提交 (Read Uncommitted)**|允许|允许|允许|很少使用|
|**读已提交 (Read Committed)**|禁止|允许|允许|Oracle/SQL Server 默认|
|**可重复读 (Repeatable Read)**|禁止|禁止|禁止（InnoDB部分解决）|**MySQL 默认**|
|**串行化 (Serializable)**|禁止|禁止|禁止|性能最差|

### 关键名词解释：

- **脏读**：读到了其他事务还没提交的数据。
	举个例子：
	- A：把余额 100 → 200（未提交）
	- B：读到余额 = 200
	- A：回滚（其实还是 100）
	问题本质：
	👉 B 读到了一个**根本不存在的结果**（未来可能消失的数据）
    
- **不可重复读**：同一个事务内，多次读取同一行数据，结果不一样（因为别人改了）。
	举个例子：
	- B：第一次读余额 = 100
	- A：修改并提交 → 200
	- B：第二次读余额 = 200
	问题本质：
	👉 数据是**真实存在的，但不稳定**
    
- **幻读**：同一个事务内，多次查询某个范围的记录，发现多了或少了行（因为别人增删了）。
	举个例子，假设有一张订单表：
	``事务 B：``
```
SELECT * FROM orders WHERE price > 100;-- 查到 5 条
```
	事务 A（并发执行）：
```
INSERT INTO orders VALUES (..., price=150);COMMIT;
```
	事务 B 再查一次：
```
SELECT * FROM orders WHERE price > 100;-- 查到 6 条 ❗
```

👉 多出来的这一行，就像“凭空出现的幻影”  
👉 所以叫：**幻读**

| 类型    | 操作对象     | 变化内容           |
| ----- | -------- | -------------- |
| 不可重复读 | 同一行数据    | 值变了（100 → 200） |
| 幻读    | 一批数据（范围） | 行数变了（5条 → 6条）  |

## 二、 MVCC 原理详解

**MVCC (Multi-Version Concurrency Control)** 意为多版本并发控制。它的存在是为了实现“读-写”冲突时不加锁，提高并发性能。

### 1. 三个隐式字段

InnoDB 会在每行记录后面保存三个隐藏列：

- **DB_TRX_ID**：最后一次插入或更新该行的**事务 ID**。
    
- **DB_ROLL_PTR**：**回滚指针**，指向该行记录的上一个版本（在 Undo Log 中）。
    
- **DB_ROW_ID**：隐藏的主键（如果表没定义主键）。

### 2. Undo Log (回滚日志)

当一个事务修改记录时，InnoDB 会把旧版本的数据复制到 Undo Log 中。通过回滚指针，这些旧版本串联成一条**版本链**。

### 3. ReadView (一致性视图)

这是 MVCC 的核心。当事务执行快照读（普通的 SELECT）时，会生成一个 ReadView。它包含四个核心字段：

1. **m_ids**：当前活跃（未提交）的事务 ID 列表。
    
2. **min_trx_id**：m_ids 中最小的值。
    
3. **max_trx_id**：系统即将分配给下一个事务的 ID 值。
    
4. **creator_trx_id**：创建该 ReadView 的事务 ID。

### 4. 数据可见性算法

当事务查询某行记录时，会根据版本链中的 `DB_TRX_ID` 与 ReadView 进行比对：

- 如果 `DB_TRX_ID < min_trx_id`：说明该版本在快照创建前已提交，**可见**。
    
- 如果 `DB_TRX_ID >= max_trx_id`：说明该版本在快照创建后才开启，**不可见**。
    
- 如果 `min_trx_id <= DB_TRX_ID < max_trx_id`：
    
    - 若在 `m_ids` 列表中：说明事务还没提交，**不可见**。
        
    - 若不在 `m_ids` 列表中：说明事务已提交，**可见**。

## 三、 不同隔离级别下的 MVCC 表现

- **RC (读已提交)**：**每次执行 SELECT** 都会生成一个新的 ReadView。所以能读到别人刚提交的修改，导致不可重复读。
    
- **RR (可重复读)**：**仅在第一次执行 SELECT** 时生成 ReadView，后续查询复用同一个。所以整个事务期间看到的数据是一致的。

> **注意**：MVCC 主要解决的是**快照读**（普通的 SELECT）的并发问题。对于**当前读**（SELECT ... FOR UPDATE, UPDATE, DELETE），InnoDB 通过 **Next-Key Locks (行锁+间隙锁)** 来防止幻读。
