### 1. Memory (堆引擎)

这种引擎完全在**内存**中存储数据，速度快到飞起。

- **特性**：由于数据在内存中，一旦数据库重启，**数据会全部丢失**，但表结构会保留。它使用哈希索引（Hash Index）。
    
- **适用场景**：
    
    - 作为临时表的缓存。
        
    - 存储不重要的、可以随时重新生成的中间计算结果。
        

### 2. Archive (存档引擎)

顾名思义，它是为了大量历史数据存档而生的。

- **特性**：只支持 `INSERT` 和 `SELECT` 操作，**不支持修改和删除**。它会对数据进行极致的压缩（通常能达到 1:10 的压缩率）。
    
- **适用场景**：
    
    - 日志记录。
        
    - 海量历史流水数据的备份。
        

### 3. Federated (联邦引擎)

它更像是一个“传送门”。

- **特性**：它本身不存储任何数据，而是指向远程 MySQL 服务器上的一个表。当你查询本地的 Federated 表时，它会从远程服务器抓取数据。
    
- **适用场景**：
    
    - 跨服务器的数据整合。
        
    - 分布式数据库的简单初步实现。
        

### 4. CSV (逗号分隔值引擎)

它把数据直接存储为普通的文本文件。

- **特性**：你可以直接用 Excel 或记事本打开数据文件并编辑。它不支持索引。
    
- **适用场景**：
    
    - 作为数据交换的中间格式。
        
    - 方便地将数据库中的数据导出给其他不使用数据库的软件。
        

### 5. Blackhole (黑洞引擎)

正如其名，数据进去就“消失”了。

- **特性**：写入的数据会被丢弃，查询永远返回空。但它会记录 **Binary Log**（二进制日志）。
    
- **适用场景**：
    
    - 用于复杂的复制（Replication）架构，只作为中转站记录日志，不占用本地存储。
        

---

### 各种引擎对比一览表

|**存储引擎**|**存储介质**|**事务支持**|**锁粒度**|**特出功能**|
|---|---|---|---|---|
|**Memory**|内存|否|表级锁|极速，断电即失|
|**Archive**|磁盘|否|行级锁|高压存储，只增查|
|**CSV**|文本|否|表级锁|通用性极强|
|**Federated**|远程|否|取决于远程|跨服务器访问|
|**Blackhole**|无|否|N/A|只记日志，不存数据|
