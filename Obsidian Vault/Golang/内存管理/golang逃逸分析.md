
# Go 内存逃逸分析指南

## 一、 必定逃逸场景

> [!abstract] 核心逻辑
> 
> 当变量的生命周期**超出其所在的栈帧**，或编译器**无法追踪其去向**时，变量会逃逸到堆上。

### 1. 返回局部变量的指针

```
func f() *int {
    x := 42
    return &x  // x 逃逸：函数结束后栈帧销毁，指针必须指向堆
}
```

### 2. 闭包捕获变量且闭包逃出函数

```
func f() func() int {
    x := 100
    return func() int { return x }  // x 逃逸：闭包被返回，其引用的变量必须常驻堆区
}
```

### 3. 传给外部包的 `interface{}` / `any` 参数

```
fmt.Println(x)  // x 逃逸：fmt 包是外部包，编译器不进行跨包逃逸分析，采取保守策略
```

### 4. 指针被存入逃逸的容器

```
func f() []*int {
    s := make([]*int, 0)
    v := 1
    s = append(s, &v)
    return s  // v 逃逸（传递性：s 逃逸 -> &v 逃逸 -> v 逃逸）
}
```

### 5. 赋值给全局变量/包级变量

```
var global *int
func f() {
    x := 42
    global = &x  // x 逃逸：全局变量生命周期长于函数
}
```

### 6. 大对象

- **规则**：通常大于 **32KB** 的 slice、数组等，由运行时直接在 `mheap` 分配。
---

## 二、 不逃逸场景（留在栈上）

|**场景**|**原因**|
|---|---|
|**返回值而非指针** `return x`|值拷贝，接收方会在自己的栈帧复制一份，不需要堆|
|**闭包在函数内使用完**|闭包生命周期未超出当前函数作用域|
|**同包函数且参数未泄露**|编译器可以进行包内跨函数静态分析|
|**忽略处理** `_ = v`|什么都没做，编译器明确知道 `v` 未泄露|

---

## 三、 核心判断原则

### 1. 生命周期判断

变量的生命周期是否超出其所在的栈帧？

### 2. 逃逸路径

- **直接逃逸**：变量本身（或其指针）被返回或存入全局。
    
- **传递性逃逸**：变量没直接逃逸，但它的指针存入了一个会逃逸的容器（如 Slice、Map）。
    

---

## 四、 编译器的局限性

> [!warning] 编译器的“保守”策略
> 
> 编译器为了保证安全性，在看不透代码意图时，宁可让其逃逸到堆，也不敢让程序崩溃。

- **不跨包分析**：传给外部包的 `interface{}` 会被保守当作逃逸。
    
- **不做全程序分析**：只在编译期逐包（package-by-package）分析。
    
- **interface{} 装箱**：值类型转换为接口类型（Boxing）通常涉及堆分配。
    

---

## 五、 性能优化实践建议

1. **优先返回值而非指针**：对于小型结构体，值拷贝通常比指针引用的堆分配开销更小。
    
2. **减少 interface{} 使用**：利用泛型（Go 1.18+）或具体类型减少装箱操作。
    
3. **警惕热路径下的打印**：调试完记得删除高频循环中的 `fmt.Println`。
    
4. **闭包限制**：尽量在函数内部消费闭包，避免将其作为返回值。
    
5. **科学验证**：使用以下命令查看编译器结论，不要盲目猜测：
    
    ```
   go build -gcflags='-m -l' main.go
    ```
