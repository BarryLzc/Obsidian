## 问题1:  SendFullMsgAsync内的 defer是否一定执行

**不一定。关键在于 `SendFullMsgAsync` 是否还会执行 callback。**

你的代码：

```
asyncErr := gopulsar.SendFullMsgAsync(
    ...,
    func(...) {
        defer once.Do(wg.Done)

        if callbackErr != nil {
            ...
        }
    },
)

if asyncErr != nil {
    recordErr(asyncErr)
    once.Do(wg.Done)
}
```

这里有两个完全独立的路径：

```
SendFullMsgAsync()
      │
      ├── 返回 asyncErr != nil
      │       ↓
      │   once.Do(wg.Done)
      │
      └── callback 被调用
              ↓
          defer once.Do(wg.Done)
```

### 如果 `asyncErr != nil`

当前这次调用会立即执行：

```
once.Do(wg.Done)
```

但是：

> **不会因为 `asyncErr != nil`，就自动触发 callback 里面的 `defer`。**

`defer` 只属于这个 callback 函数：

```
func(...) {
    defer once.Do(wg.Done)
    ...
}
```

只有 **这个 callback 函数真正被调用了**，它的 `defer` 才会注册并最终执行。

---

### 举个例子

假设：

```
SendFullMsgAsync(...) → error
```

并且它保证失败时**不会调用 callback**：

```
SendFullMsgAsync()
       ↓
   asyncErr != nil
       ↓
once.Do(wg.Done)
       ↓
    继续执行
```

callback 根本没执行：

```
func(...) {
    defer once.Do(wg.Done) // 没有执行
}
```

所以这个 `defer` 也不会发生。

---

### 但如果它是这种行为

```
SendFullMsgAsync()
       │
       ├── 返回 asyncErr
       │       ↓
       │   once.Do(wg.Done)
       │
       └── 后面又调用 callback
               ↓
           defer once.Do(wg.Done)
```

那么 callback 的 `defer` **会执行**。

但是由于你用了：

```
sync.Once
```

第二次：

```
once.Do(wg.Done)
```

不会再执行 `wg.Done()`。

因此最终仍然只有：

```
wg.Add(1)
    ↓
第一次 Done
    ↓
wg = 0
```

不会出现：

```
wg.Add(1)
wg.Done()
wg.Done() // panic
```

---

### 所以这段代码为什么需要 `once`

它实际上是在处理：

```
                  ┌─ asyncErr ──→ Done
SendFullMsgAsync ─┤
                  └─ callback ──→ defer → Done
```

**无论哪条路径最终发生，`wg.Done()` 只允许执行一次。**

这也是这里 `sync.Once` 最核心的作用。

你可以把：

```
defer once.Do(wg.Done)
```

理解成：

> “如果 callback 被调用，那么 callback 退出时尝试 Done；但如果之前已经因为 `asyncErr` Done 过了，就什么都不做。”

所以回答你的问题：

**`asyncErr != nil` 本身不会触发 callback 的 `defer`。只有 callback 实际被调用并开始执行后，defer 才会生效。**

## 问题2：如果不加锁会怎么样

“不加锁”是指**这里不用 `sync.Once` / `Mutex` 之类的并发保护**，要分情况看。

### 1. 你这段代码里，如果去掉 `Once`

例如：

```
wg.Add(1)

asyncErr := SendFullMsgAsync(..., func(...) {
    defer wg.Done()
})

if asyncErr != nil {
    wg.Done()
}
```

假设存在这种情况：

```
SendFullMsgAsync
      │
      ├── 返回 error
      │       ↓
      │     Done()
      │
      └── callback 又被调用
              ↓
            Done()
```

那么：

```
Add(1)
   ↓
counter = 1

第一次 Done()
   ↓
counter = 0

第二次 Done()
   ↓
counter = -1
```

可能直接：

```
panic: sync: negative WaitGroup counter
```

所以这里 `Once` 的作用是防止 **重复 Done**。

---

### 2. 但 `Once` 不是“锁住 wg”

这是一个很重要的区别。

你可能会理解成：

```
Once
 ↓
把 wg 锁住
```

实际上不是。

`Once` 保护的是：

```
once.Do(wg.Done)
```

也就是：

> **保证 `wg.Done()` 这个操作最多执行一次。**

例如两个 goroutine 同时执行：

```
once.Do(wg.Done)
```

可能是：

```
goroutine A ──┐
              ├── Once ──→ 只有一个真正执行 wg.Done()
goroutine B ──┘
```

---

### 3. 如果是共享变量 `recordErr`，情况又不一样

你这里还有：

```
recordErr(callbackErr)
```

如果 `recordErr` 内部是类似：

```
var errs []error

func recordErr(err error) {
    errs = append(errs, err)
}
```

而多个 callback 并发执行：

```
goroutine A → recordErr()
goroutine B → recordErr()
goroutine C → recordErr()
```

那么这里就可能产生 **data race**。

这种情况下需要：

```
mu.Lock()
errs = append(errs, err)
mu.Unlock()
```

或者使用其他并发安全的数据结构。

所以：

> **是否需要 Mutex，取决于 `recordErr` 是否操作共享状态。**

---

### 4. `WaitGroup` 自己不是让你的业务数据线程安全

例如：

```
wg.Add(1)

go func() {
    sharedMap["a"] = 1
    wg.Done()
}()

go func() {
    sharedMap["b"] = 2
    wg.Done()
}()

wg.Wait()
```

`WaitGroup` 只负责：

```
“等两个 goroutine 做完”
```

它**不会保护 `sharedMap`**。

如果两个 goroutine 同时操作普通 `map`，仍然可能出问题。

所以可以把几个工具的职责记成：

```
WaitGroup
    ↓
什么时候结束？

Once
    ↓
最多执行一次？

Mutex
    ↓
谁现在可以访问共享资源？

Channel
    ↓
goroutine 之间怎么安全地传递数据？
```

---

### 回到你的代码

你这里最关键的是：

```
defer once.Do(wg.Done)
```

和：

```
if asyncErr != nil {
    once.Do(wg.Done)
}
```

**如果你确定 callback 和 `asyncErr` 两条路径绝对不会同时触发，那么可以不需要 `Once`。**

但如果不能保证，那么去掉它最大的风险就是：

```
wg.Done() 被调用两次
        ↓
WaitGroup counter 变负数
        ↓
panic
```

而如果你说的“不加锁”是指 **`recordErr` 不加 Mutex 会怎么样**，那要看 `recordErr` 的具体实现；如果你贴一下 `recordErr`，我可以直接判断这里有没有 data race。

## 知识点总结
### 1. `sync.WaitGroup`：等待一批异步任务完成

你的代码：

```
wg.Add(1)
```

表示：

> 有一个异步任务需要等待。

然后：

```
wg.Done()
```

表示：

> 这个异步任务完成了。

最后：

```
wg.Wait()
```

表示：

> 等所有任务完成之后再继续。

例如：

```
for _, msg := range msgs {
    wg.Add(1)

    SendAsync(msg, func() {
        wg.Done()
    })
}

wg.Wait()
```

如果有 3 个 msg：

```
Add(1) → Add(1) → Add(1)
  1          2          3
                       ↓
                    Wait()
                       ↓
              等待 counter = 0
```

---

### 2. `wg.Add(1)` 为什么放在 for 里面？

因为：

> **每一个 msg 都对应一个独立的异步任务。**

例如：

```
for _, msg := range msgs {
    wg.Add(1)
}
```

10 个 msg：

```
msg1 → +1
msg2 → +1
msg3 → +1
...
msg10 → +1

WaitGroup counter = 10
```

如果只写：

```
wg.Add(1)

for _, msg := range msgs {
    SendAsync(...)
}
```

那 WaitGroup 只认为存在 **1 个任务**，而实际上你启动了很多异步任务。

---

### 3. `sync.Once`：保证代码最多执行一次

你的代码：

```
var once sync.Once

once.Do(wg.Done)
```

意思不是：

> 加一把锁。

而是：

> **无论多少 goroutine 调用 `once.Do(...)`，里面的函数最多成功执行一次。**

例如：

```
once.Do(wg.Done)
once.Do(wg.Done)
once.Do(wg.Done)
```

实际上：

```
第一次 → wg.Done() ✅
第二次 → 不执行
第三次 → 不执行
```

---

### 4. 为什么这里需要 `Once`？

因为你的任务存在多个完成路径：

```
SendFullMsgAsync
       │
       ├── 返回 asyncErr
       │       ↓
       │     Done()
       │
       └── callback
               ↓
             Done()
```

假设：

```
wg.Add(1)
```

然后：

```
asyncErr → Done()
callback → Done()
```

就会变成：

```
1 → 0 → -1
```

最终可能：

```
panic: sync: negative WaitGroup counter
```

所以：

```
once.Do(wg.Done)
```

保证：

```
asyncErr → Done()  ← 第一次执行
callback → Done()  ← 第二次不执行
```

最终只会：

```
1 → 0
```

---

### 5. `defer`：函数退出时执行

你的 callback：

```
func(...) {
    defer once.Do(wg.Done)

    if callbackErr != nil {
        ...
    }
}
```

这里：

```
defer once.Do(wg.Done)
```

**不是立即执行**。

而是：

```
进入 callback
    ↓
注册 defer
    ↓
执行 callback 里面的代码
    ↓
callback 即将返回
    ↓
执行 once.Do(wg.Done)
```

所以它非常适合做：

```
defer cleanup()
```

这种“无论中间发生什么，函数退出时都要做”的事情。

---

### 6. `defer` 并不是绝对执行

正常情况下：

```
return
```

或者：

```
panic
```

都会触发已经注册的 `defer`。

但是：

```
os.Exit()
```

不会执行 defer。

进程被：

```
kill -9
```

也不会执行。

所以更准确的说法是：

> **只要函数正常返回或发生 panic，已经注册的 defer 会执行；进程被强制终止则不会。**

---

### 7. `asyncErr != nil` 不代表 callback 一定执行

**这是最容易混淆的地方**

```
asyncErr := SendFullMsgAsync(..., callback)
```

如果：

```
asyncErr != nil
```

你执行：

```
once.Do(wg.Done)
```

**不会自动触发 callback。**

因为：

```
defer once.Do(wg.Done)
```

属于：

```
func(...) {
    ...
}
```

只有 callback **真正被调用**：

```
callback(...)
```

它里面的 defer 才会注册并执行。

所以：

```
asyncErr != nil
    ↓
Done()

≠

callback 被调用
    ↓
defer Done()
```

这是两个独立的事情。

---

### 8. `Mutex` 和 `Once` 不要混淆
#### `Mutex`

```
mu.Lock()

sharedData++

mu.Unlock()
```

解决的是：

> **同一时间只能让一个 goroutine 进入临界区。**

也就是：

```
goroutine A → Lock → 执行 → Unlock
                         ↓
goroutine B → 等待 ──────┘
```

---

#### `Once`

```
once.Do(func() {
    init()
})
```

解决的是：

> **这段代码整个生命周期最多执行一次。**

所以：

|工具|核心作用|
|---|---|
|`Mutex`|同一时间只有一个 goroutine 进入临界区|
|`RWMutex`|多个读可以并发，写需要独占|
|`Once`|某段代码最多执行一次|
|`WaitGroup`|等待一组异步任务完成|

---

## 9. 你这段代码整体可以这样理解

把代码抽象一下：

```
for _, msg := range msgs {

    // ① 告诉 WaitGroup：
    //    我要等待这个异步任务
    wg.Add(1)

    // ② 每个 msg 有自己的 Once
    var once sync.Once

    asyncErr := SendAsync(msg, func() {

        // ③ callback 结束时尝试 Done
        defer once.Do(wg.Done)

        ...
    })

    // ④ 如果发送函数直接返回错误
    if asyncErr != nil {

        // ⑤ 也尝试 Done
        once.Do(wg.Done)
    }
}

// ⑥ 等所有 msg 完成
wg.Wait()
```

可以画成：

```
                    msgs
                      │
          ┌───────────┼───────────┐
          ↓           ↓           ↓
        msg1        msg2        msg3
          │           │           │
        Add(1)      Add(1)      Add(1)
          │           │           │
          ↓           ↓           ↓
       SendAsync   SendAsync   SendAsync
          │           │           │
       ┌──┴──┐     ┌──┴──┐     ┌──┴──┐
       │     │     │     │     │     │
    error callback ...             ...
       │     │
       └──┬──┘
          ↓
       Once.Do
          ↓
       wg.Done()
          │
          ↓
       counter = 0
          │
          ↓
       wg.Wait()
          │
          ↓
       继续执行
```

## 总结

这段代码的设计思想就是：

> **`WaitGroup` 管“什么时候全部完成”，`Once` 管“每个任务只能完成一次”，`defer` 管“callback 退出时自动完成”，而 `asyncErr` 和 callback 是两条可能的完成路径。**

这四个概念理解清楚以后，你以后看到 Go 里面这种 **异步 RPC / MQ / HTTP callback + WaitGroup** 的代码，基本就能快速读懂了。
