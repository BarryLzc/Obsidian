**最准确判断驱动表的方法：看 EXPLAIN 执行计划**
# 1. 什么是驱动表？

例如：

```
SELECT *FROM user uJOIN orders oON u.id = o.user_id
```

如果执行流程是：

```
1. 先查 user2. 再拿 user.id 去 orders 查
```

那么：

```
user = 驱动表orders = 被驱动表
```

---

# 2. MySQL JOIN 底层（非常重要）

MySQL 大多数 JOIN 使用：

```
Nested Loop Join（嵌套循环）
```

本质：

```
for user in users: 去 orders 查匹配数据
```

所以：

```
外层循环 = 驱动表
```

---

# 3. 怎么看驱动表？

直接：

```
EXPLAIN SELECT ...
```

例如：

```
EXPLAINSELECT *FROM user uJOIN orders oON u.id = o.user_idWHERE u.status = 1;
```

可能结果：

|table|type|rows|
|---|---|---|
|u|ref|10|
|o|ref|5|

这里：

```
u 在前
```

说明：

```
先扫描 u
```

因此：

```
u 是驱动表
```

然后：

```
根据 u.id 去查 o
```

---

# 4. EXPLAIN 怎么判断（重点）

通常：**EXPLAIN 输出顺序**，就是：**JOIN 执行顺序**

前面的：

```
驱动表
```

后面的：

```
被驱动表
```

---

# 5. 一个非常关键的点

SQL 写的顺序：

```
FROM A JOIN B
```

不一定：

```
A 就是驱动表
```

因为：

```
MySQL 优化器会自动调整 JOIN 顺序
```

例如：

```
FROM big_tableJOIN small_table
```

优化器可能实际：

```
先查 small_table
```

因为成本更低。

---

# 6. MySQL 怎么决定驱动表？

优化器会估算：

|因素|含义|
|---|---|
|rows|预计扫描行数|
|索引命中|是否能快速查|
|where过滤率|能过滤多少|
|cardinality|区分度|
|cost|总成本|

最终选择：

```
cost 最低
```

的方案。

---

# 7. 一般什么表容易成为驱动表？

## （1）过滤后数据少的表（通常情况）

例如：

```
WHERE status = 1
```

只剩 10 条。

适合驱动。

---

## （2）能命中高效索引的表

例如：

```
WHERE id = 1
```

主键查询。

非常适合驱动。

---

## （3）小结果集

因为：Nested Loop：O(n×m)，外层循环越少越好。

# 总结

在 MySQL 中：

```
一般推荐小结果集驱动大结果集
```

因为 JOIN 底层通常采用：

```
Nested Loop Join
```

可以减少循环次数。

但真正决定驱动顺序的是：

```
MySQL 优化器
```

优化器会根据：

- 数据量
- 索引
- 过滤条件
- 统计信息

自动选择最优执行计划。

另外：

```
被驱动表的 JOIN 字段必须有索引
```

否则 JOIN 性能会很差。
