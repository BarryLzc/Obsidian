概述：现代[[操作系统]]大多拥有两种工作状态，分别是内核态和用户态。将传统的操作系统代码放置到更高层，从操作系统中去掉尽可能多的东西，而只留下最小的核心，称之为微内核。（C/S结构 - 客户进程/进程服务器）![[单体内核&微内核.png]]微内核操作系统适用于分布式系统中
微内核：mach
混合内核：macOS
单体内核：linux

| 维度           | Mach 微内核                        | Linux 单体内核          |
| ------------ | ------------------------------- | ------------------- |
| **系统服务运行位置** | 许多服务（驱动、文件系统）运行在用户空间            | 所有核心服务运行在内核空间       |
| **通信方式**     | 基于消息传递（IPC） → 性能损耗高             | 内核内函数调用 → 性能更高      |
| **稳定性**      | 服务崩溃不影响内核，可单独重启                 | 模块崩溃可能导致整个系统崩溃      |
| **安全性**      | 较高，服务隔离                         | 较低，共享地址空间           |
| **扩展性/可移植性** | 更好，可替换服务模块                      | 较差，修改影响全局           |
| **性能**       | 较低（多次上下文切换与消息复制）                | 较高（直接调用，无额外IPC）     |
| **复杂度**      | 内核小，架构复杂                        | 内核大，代码量多但执行路径简单     |
| **代表系统**     | macOS (Mach + BSD), QNX, MINIX3 | Linux, BSD, Solaris |
