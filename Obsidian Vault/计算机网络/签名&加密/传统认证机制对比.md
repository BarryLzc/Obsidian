
# 核心特征对比
| **认证机制 (Mechanism)**                      | **接纳模式 (Onboarding)**      | **凭证交换方式 (Credential Exchange)**                                           | **认证协议层级 (Protocol Layer)** | **核心应用场景与痛点差异**                                                                                   |
| ----------------------------------------- | -------------------------- | -------------------------------------------------------------------------- | --------------------------- | ------------------------------------------------------------------------------------------------- |
| **[[HTTP Message Signatures(RFC 9421)]]** | **Permissionless**（无需预先许可） | **非对称公钥自发现**<br><br>  <br><br>(通过 Profile/DID 获取公钥，无需带外协商)                 | 应用层 (HTTP Header 局部或全量签名)   | **去中心化 Commerce/Agent 交互**。<br><br>  <br><br>服务端通过 `UCP-Agent` 找到 Profile 获取公钥解密验签，适合未知节点间直接建立信任。 |
| **OAuth 2.0**                             | **Pre-established**（需预先建立） | **授权码/Client Credentials**<br><br>  <br><br>(需要注册 App 获得 Client ID/Secret) | 应用层 (Bearer Token 方式传递)     | **中心化/已有信任链的授权**。<br><br>  <br><br>适合三方应用接入、带用户上下文授权的 REST API 交互。                                |
| **API Keys**                              | **Pre-established**（需预先建立） | **共享对称密钥 (Pre-shared Secret)**<br><br>  <br><br>(需在后台人工生成或 API 申请)         | 应用层 (Header 携带明文/简单 HMAC)   | **传统 SaaS / Webhook 回调**。<br><br>  <br><br>简单但存在密钥泄露风险，难以防范请求重放或中间人篡改。                            |
| **mTLS**                                  | **Pre-established**（需预先建立） | **双向数字证书 (X.509 Certificate)**<br><br>  <br><br>(需 PKI 体系或预置 CA 根证书)       | 传输层 (TLS Handshake 阶段)      | **网关与网关间的零信任通信**。<br><br>  <br><br>安全性极高，但建立成本大，不支持 CDN/反向代理层解密后的端到端报文完整性。                        |
