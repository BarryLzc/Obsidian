**HTTP 1.1**（HyperText Transfer Protocol Version 1.1）是互联网上应用最广泛的一种网络协议。它于 1997 年正式发布（RFC 2068），并在 1999 年得到进一步完善（RFC 2616）。

作为 HTTP 1.0 的继任者，它修复了早期协议中的许多缺陷，是现代 Web 通信的基石。

---

## HTTP 1.1 的核心改进

相比于早期的 HTTP 1.0，HTTP 1.1 引入了几个关键特性，极大地提升了网页加载效率：

### 1. 持久连接 (Persistent Connections)

- **1.0 版本：** 每请求一个资源（如一张图片或一个 CSS 文件）都需要建立一次 TCP 连接，结束后立即断开。这种“短连接”会导致大量的时间浪费在三次握手上。
    
- **1.1 版本：** 默认开启 **Connection: keep-alive**。浏览器和服务器之间可以复用同一个 TCP 连接来发送多个请求，显著降低了延迟。

### 2. 管线化技术 (Pipelining)

在同一个持久连接上，客户端可以连续发送多个请求，而不需要等待前一个请求的响应。不过，由于它无法完全解决“队头阻塞”问题（响应必须按顺序返回），该技术在现代浏览器中并未被广泛采用。

### 3. 分块传输编码 (Chunked Transfer Encoding)

HTTP 1.1 允许服务器在还不知道内容最终大小时就开始发送响应。服务器将数据分成一个个“块”（Chunks）进行传输，这对于动态生成的网页内容非常有用。

### 4. 增强的缓存控制

引入了更多的缓存处理指令，如 `Cache-Control`、`ETag` 和 `If-None-Match`。相比 1.0 仅靠 `Expires` 这种依赖客户端时间的判断方式，1.1 的缓存机制更加精准和灵活。

### 5. 虚拟主机支持 (Host 头部)

HTTP 1.1 要求请求头中必须包含 **Host** 字段。这使得一台物理服务器（同一个 IP 地址）可以同时托管多个域名（网站），这是现代云计算和虚拟主机的基础。这也是目前[[CDN]]技术的基石

## HTTP 1.1 的工作模型

在 HTTP 1.1 中，典型的交互流程如下：

1. **建立连接：** 客户端与服务器通过 TCP 三次握手建立连接。
    
2. **发送请求：** 客户端通过该连接发送第一个请求（如 `index.html`）。
    
3. **保持连接：** 服务器返回 HTML 后，连接并不关闭。
    
4. **复用连接：** 客户端继续通过同一个连接请求 HTML 中引用的 JS、CSS 或图片。
    
5. **关闭连接：** 当一段时间没有活动后，连接才会超时关闭。

---

## 局限性

尽管 HTTP 1.1 非常强大，但它也存在一些瓶颈：

- **队头阻塞 (Head-of-Line Blocking)：** 虽然可以复用连接，但请求必须按顺序处理。如果第一个请求处理很慢，后面的请求都会被阻塞。
    
- **头部冗余：** 每次请求都要携带大量重复的 HTTP Header，浪费带宽。

这些问题最终促使了 **[[HTTP2 性能的跨越式提升]]**（支持多路复用）和 **[[HTTP3 推导重来的革命]]**（基于 QUIC 协议）的诞生。但在今天，绝大多数服务器依然完美向下兼容 HTTP 1.1。

|**特性**|**HTTP 1.0**|**HTTP 1.1**|
|---|---|---|
|**连接模型**|短连接 (每请求一连)|**持久连接 (默认开启)**|
|**带宽利用**|必须传输全量文件|**支持断点续传 (Range)**|
|**缓存机制**|较简单 (Expires)|**丰富灵活 (Cache-Control, ETag)**|
|**单IP多域名**|不支持 (无 Host 头)|**支持 (必须有 Host 头)**|
|**传输模式**|需确定内容长度|**支持分块传输 (Chunked)**|

|**特性**|**HTTP 1.1**|**HTTP 2**|**HTTP 3**|
|---|---|---|---|
|**底层传输协议**|TCP|TCP|**UDP (QUIC)**|
|**传输格式**|文本|**二进制帧**|**二进制帧**|
|**多路复用**|无（有队头阻塞）|**有（但在 TCP 层仍有阻塞）**|**有（彻底解决队头阻塞）**|
|**头部压缩**|无|**HPACK**|**QPACK**|
|**安全性**|可选 (HTTPS)|**事实上强制 (TLS 1.2+)**|**内置强制加密 (TLS 1.3)**|
|**握手延迟**|高 (TCP + TLS)|高 (TCP + TLS)|**极低 (0-RTT/1-RTT)**|
