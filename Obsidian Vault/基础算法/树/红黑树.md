红黑树（Red-Black Tree）的定义其实就是一组**为了维持树的“大致平衡”而制定的硬性规则**。

在数据结构中，它被定义为一种**自平衡的二叉查找树**。为了保证从根到叶子的最长路径不会超过最短路径的两倍，它必须严格遵守以下 **5 个特性**：

---

### 1. 红黑树的 5 大定义特性

1. **节点颜色**：每个节点要么是**红色**，要么是**黑色**。
    
2. **根节点**：根节点（Root）必须是**黑色**。
    
3. **叶子节点**：所有的 NIL 节点（空节点）都被视为**黑色**。
    
4. **红色限制**：如果一个节点是红色的，那么它的两个子节点都必须是黑色的（即：**不能有两个连续的红色节点**）。
    
5. **黑高一致**：从任一节点到其每个叶子的所有简单路径，都包含**相同数量的黑色节点**。
### 2. 形象理解

假设我们关注的当前节点是 **N (Node)**：

- **父节点 (P - Parent)**：直接连接在 N 之上的节点。
    
- **祖父节点 (G - Grandparent)**：P 的父节点。
    
- **叔叔节点 (U - Uncle)**：**祖父节点 G 的另一个子节点**。也就是说，它是你父亲的亲兄弟。
    

---

### 3. 图解关系

我们可以通过下面这个简单的结构看清楚他们的位置：

- 如果 **P** 是 **G** 的**左孩子**，那么 **U** 就是 **G** 的**右孩子**。
    
- 如果 **P** 是 **G** 的**右孩子**，那么 **U** 就是 **G** 的**左孩子**。
    

---

### 4. 为什么“叔叔”在红黑树中很重要？

在红黑树插入新节点后的**自平衡（修复）**过程中，叔叔节点的**颜色**是决定“接下来该怎么办”的关键：

- **如果叔叔是红色**：说明爷爷节点有两个红色的儿子。这时候不需要旋转，只需要通过**变色**（把父和叔变黑，爷爷变红）就能把红色压力向上传递。
    
- **如果叔叔是黑色（或者是空的 NIL 节点）**：说明树已经严重倾斜了。这时候仅仅靠变色无法解决问题，必须通过**旋转（左旋或右旋）**来强行改变树的结构，达到平衡。
---

### 5. 核心修复场景分类

假设新插入节点为 `N`，其父节点为 `P`，祖父节点为 `G`，叔叔节点（`P` 的兄弟）为 `U`。

#### 场景 A：叔叔节点 `U` 是红色的（变色即可）

- **处理方法**：
    
    1. 将 `P` 和 `U` 设为黑色。
        
    2. 将 `G` 设为红色。
        
    3. 把 `G` 当作当前节点，向上递归检查（因为 `G` 变红可能导致它的父节点也红）。
        
- **直观感受**：这种情况下不需要旋转，只需要把红色“向上传递”。
    

#### 场景 B：叔叔节点 `U` 是黑色的，且 `N` 是“外侧”子节点

- **外侧定义**：`P` 是 `G` 的左子，`N` 也是 `P` 的左子；或同为右子。
    
- **处理方法（以左左为例）**：
    
    1. 对 `G` 进行 **右旋**。
        
    2. 交换旋转前 `P` 和 `G` 的颜色。
        
- **结果**：原来的父节点变成了新的根，结构恢复平衡。
    

#### 场景 C：叔叔节点 `U` 是黑色的，且 `N` 是“内侧”子节点

- **内侧定义**：`P` 是 `G` 的左子，`N` 却是 `P` 的右子。
    
- **处理方法**：
    
    1. 先对 `P` 进行 **左旋**，将“内侧”问题转化成“外侧”问题（变成场景 B）。
        
    2. 再按照场景 B 的方法对 `G` 进行旋转和变色。
        

---

### 6. Java 8 源码中的实现：`balanceInsertion`

在 `HashMap.TreeNode` 类中，这个逻辑被实现在 `balanceInsertion` 方法里。我们可以通过一段伪代码来解析它的核心逻辑：

Java

```
static <K,V> TreeNode<K,V> balanceInsertion(TreeNode<K,V> root, TreeNode<K,V> x) {
    x.red = true; // 新节点默认为红
    for (TreeNode<K,V> xp, xpp, xppl, xppr;;) {
        // 如果 x 是根，设为黑，直接返回
        if ((xp = x.parent) == null) {
            x.red = false;
            return x;
        }
        // 如果父节点是黑，或者父节点就是根，不需要修复
        else if (!xp.red || (xpp = xp.parent) == null)
            return root;

        // --- 以下是双红情况 ---
        if (xp == (xppl = xpp.left)) { // 父节点在左边
            if ((xppr = xpp.right) != null && xppr.red) { // 场景 A：叔叔是红
                xppr.red = false;
                xp.red = false;
                xpp.red = true;
                x = xpp; // 向上递归
            } else { // 场景 B & C：叔叔是黑
                if (x == xp.right) { // 场景 C：内侧
                    root = rotateLeft(root, x = xp); // 先左旋变外侧
                    xpp = (xp = x.parent) == null ? null : xp.parent;
                }
                if (xp != null) { // 场景 B：外侧
                    xp.red = false;
                    if (xpp != null) {
                        xpp.red = true;
                        root = rotateRight(root, xpp); // 再右旋
                    }
                }
            }
        } else {
            // ... (父节点在右边的对称操作)
        }
    }
}
```

## 7. 与其他树的对比

- **对比二叉查找树 (BST)**：BST 在极端情况下会退化成链表，而红黑树通过旋转保持平衡。
    
- **对比平衡二叉树 (AVL 树)**：
    
    - AVL 树是**高度平衡**的，查询更快，但插入/删除时旋转次数多。
